## Non-obvious implementation points (don't re-litigate)

### map-filters
- **`visibleLocations` predicate** in `MapPage.tsx`: selected pin always renders → active `?category=` filters at all zooms → else the zoom gate (`ZOOM_GATE = 12`, hidden below). The selected-pin exemption is *defensive dead code* in practice (external entries arrive filter-less, so the non-matching-category case can't be reached) — kept anyway for the `?fly=1` pre-resolve moment.
- **`navigateMap`** preserves `?category=` *and* `?layer=`, and deliberately drops the transient `fly` (carrying it would re-center on every in-map click).
- **`ZoomTracker`** reads the live zoom via `useMapEvents({ zoomend })` — the `MapContainer` `zoom` prop only applies on mount.
- `CategoryFilter` (chips) and `SearchBox` are **sibling overlays** of `MapContainer` (inside the `relative min-w-0 flex-1` wrapper), so they need **no** `L.DomEvent.disableClickPropagation` (only `LocateButton`, which lives *inside* the map, needs it).

### tile-layers
- **`TileLayerController`** swaps the base layer imperatively on `layer.id` — vector via `maplibreGL({ style, attributionControl: { customAttribution } })`, raster via `L.tileLayer`. Note the MapLibre adapter's option is **`attributionControl: { customAttribution }`**, *not* a top-level `attribution` (the original ticket was wrong here).
- **maplibre worker**: `main.tsx` does `setWorkerUrl(workerUrl)` with `import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url'`; `vite-env.d.ts` declares `*?worker&url`.
- **Thumbnails are the soft spot**: `topo.png` is a real OpenTopoMap tile; the three OpenFreeMap ones are **gradient placeholders** generated by `frontend/scripts/generate-layer-thumbnails.mjs` (colors from each style's `background` layer). Not faithful captures — replace if a real preview is needed.

### search (the heavy one)
- **pgvector is compiled into the db image** (`db/Dockerfile`, v0.7.4, into `postgis:16-3.4-alpine`). It needs **`clang15 llvm15`** for PG16's LLVM bitcode step — without them `make` fails with `clang-15: No such file or directory`.
- **transformers.js v4 defaults to fp32** (`model.onnx`, ~470 MB). The pipeline is called with `{ dtype: 'q8' }` so it uses the baked `model_quantized.onnx` (~120 MB). Don't drop the `dtype`.
- **The model is baked into BOTH `Dockerfile` and `Dockerfile.dev`** (they're separate — the compose `api` service uses `Dockerfile.dev`). A model stage downloads at *build time* (runtime has no network). `env.localModelPath = '/app/models/embedding'`.
- **`libgomp1`** must be installed (onnxruntime-node's OpenMP runtime) — added to both API Dockerfiles.
- **Vector writes/serialize as `[a,b,c]::vector`** strings via `$executeRaw` — Prisma can't write the `Unsupported("vector(384)")` field through the client.
- **Embed synchronously on POST/PATCH** (`embedLocationAndStore`), degrading to NULL on failure; `backfillEmbeddings()` runs at startup + every 10 min (idempotent, concurrency-guarded). `server.ts` warms the model then backfills.
- **Search endpoint** `GET /api/locations/search?q=` is registered **before `/:id`** (same trick as `nearby`). Thumbnail-enriched via a second Prisma query (pinned ?? first-by-order). Floor `0.4` is an **untuned heuristic**.
- `SearchBox` (top-center, above the chips) clears `?category=` on select but **keeps `?layer=`**.

## Migrations & how to run them

- `tsx watch` doesn't see file changes over Windows bind mounts → `docker compose restart api` after backend source edits.
- The model download runs at image build (needs internet); the runtime has none.
