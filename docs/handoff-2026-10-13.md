## Non-obvious implementation points (so they aren't re-litigated)

- **The share-slug route bug.** Route `/locations/:slug/@:coords` never matched — React Router v6 only parses `:param` when it's preceded by `/`, so the `@`-glued `:coords` was read as literal text and the router logged `No routes matched location ...` (blank map, no sidebar). Fix: `/locations/:slug/:coords`; the `@` is now part of the `coords` value and is stripped in `components/SlugResolver.tsx`. The visible URL `/locations/<slug>/@<lat>,<lng>` is unchanged.
- **`slugifyName` is Unicode-aware now**: `/[^\p{L}\p{N}]+/gu` (was `[^a-z0-9]`, which erased Cyrillic). The share URL percent-encodes the slug (`encodeURIComponent`). The name is cosmetic — coords are the lookup key — so the slug value is ignored by the resolver.
- **`buildShareUrl(name, lat, lng)` in `lib/utils.ts`** is the single source of truth for share URLs, used by both the sidebar header and `/saved` cards.
- **Fly-to is merged into `Recenter`** (`components/mapEffects.tsx`): `Recenter({ center, flyTo })` does `map.flyTo(flyTo, 15)` when a target is present, else `setView(center)`. This is deliberate: a slow geolocation resolve must not override an external-entry fly. In-place marker clicks don't pass `flyTo` (no re-center).
- **Pre-existing schema drift fixed**: the committed init migration creates `Image_userId_fkey` with `ON DELETE CASCADE`, but `schema.prisma` omitted `onDelete` (default `RESTRICT`). Added `onDelete: Cascade` to `Image.user` — a no-op for the DB, but it un-pollutes `migrate diff`. Flag this if bisecting.
- **`SavedLocation` compound key** is `userId_locationId` (used in `findUnique`). Toggle handles the P2002 double-save race by treating it as "already saved".
- **Saved-state read** is a per-user query `['location', id, 'saved']` (enabled only when logged in); POST returns the new `{ saved }` and writes it straight into that query cache + invalidates `['saved']`.
- **Category picker is a native `<select>`** (`components/ui/select.tsx`), not a Radix Select — deliberately no new dependency for a single dropdown.
- **Description clamp** (`ClampedText` in `LocationSidebar.tsx`) measures `scrollHeight > clientHeight` for the Show more/less toggle; do not switch to a length heuristic without a reason.

## Migrations & how to run them here (important)

`prisma migrate dev` **fails in this non-interactive shell** ("environment is non-interactive"). The working flow used:

1. Ensure Docker Desktop + `docker compose up -d db`.
2. `prisma migrate diff --from-url "<live db url>" --to-schema-datamodel prisma/schema.prisma --script` to get clean SQL.
   - `--from-migrations` needs a **shadow DB** (`thesis_shadow` was created then dropped); `--from-url` against the live DB avoids the shadow replay drift.
3. Write the SQL into `prisma/migrations/<timestamp>_<name>/migration.sql`, then `prisma migrate deploy`, then `prisma generate`.

The migration added this session: `20261013000000_location_category_saved_location` (enum + `category` column + `SavedLocation` table).

**After any schema change, rebuild the api image** — the Prisma client is generated at image build (`docker compose up -d --build api`); the runtime bind-mounts `src/` and `prisma/` but *not* `node_modules`.
