# Handoff — models-3d demo models + PlayCanvas SPZ v4 migration (2026-10-18)

Session context for the next agent. This session closed out `models-3d` end to
end: sourced + seeded the demo 3D models, replaced the SPZ renderer with the
PlayCanvas engine (SPZ v4), and added admin upload/delete controls + automatic
v3→v4 conversion. Read the build log (`docs/implementation-status.md` §11) for
the full narrative; this doc covers what changed and the non-obvious bits.

## What landed

1. **Demo models** (`.scratch/models-3d/issues/02`, resolved): `marble-bust.glb`
   (CC0, Poly Haven), `stone-bridge.glb` (CC0, OpenGameArt — obj→glb with an
   authored MTL), `racoonfamily.spz` (MIT, Niantic sample, now v4). Kale
   Fortress deliberately has none (shows the "no model" state). The binaries
   live in `backend/models/` — **gitignored**, never committed.
2. **Seed owns demo models** (`prisma/seed.ts`): upsert + prune mirrors the
   location seed; demo rows carry `Model.seeded = true` (migration
   `20261018000000_model_seeded`) and the prune only touches flagged rows — an
   admin upload on a seeded location survives re-seeding. A missing file skips;
   non-v4 `.spz` files are converted to v4 **in place** (idempotent, v4 left
   untouched).
3. **Models dir → bind mount**: the `models` named volume became a bind mount of
   `./backend/models` in both compose files. The baked embedding model moved
   from `/app/models/embedding` to `/app/embedding` (Dockerfile ×2 +
   `env.localModelPath`) so the mount wouldn't shadow it. Search re-verified
   (0.82 "castle" → Kale).
4. **Admin sidebar controls** (`ModelControls.tsx`): upload (single `.glb`/`.spz`
   file picker, "Uploading…" state) + delete (confirm dialog) in the sidebar's
   "3D model" section; admins see the section even when the location has no
   model. Both invalidate `['location', id]` + `['locations']`.
5. **SPZ renderer migrated to PlayCanvas**: `@mkkellogg/gaussian-splats-3d`
   (frozen at 0.4.7, reads SPZ ≤ v2) couldn't load the real Nikola Karev
   monument file (v3). `ModelViewer.tsx`'s SPZ path is now a PlayCanvas
   `Application` (gsplat entity + `SpzParser` + `CameraControls`, camera
   frame-fit to the splat's AABB, orbit-only). The GLB path (R3F) is unchanged.
   `playcanvas` npm dep + ZSTD wasm vendored in `frontend/public/wasm/`.
6. **v3→v4 conversion in the backend** (`lib/spz.ts`): `ensureSpzV4` (checks the
   `NGSP` magic; converts legacy gzip v1–3) is shared by `POST /api/models`
   (synchronous, before storing) and the seed (writes back in place). GLB
   passes through.

## Non-obvious implementation points

- `playcanvas` exports `./scripts/*` — `SpzParser` and `CameraControls` are
  importable `.mjs` scripts from the package itself;
  `types/playcanvas-scripts.d.ts` declares them (the `ResourceParser` shape
  needs `canParse` + `load` with the exact callback types).
- The PlayCanvas SPZ parser reads **only v4**; v1–3 throw "legacy gzip based
  version". Conversion uses `@playcanvas/splat-transform` in the backend:
  `readFile`/`writeSource` over `MemoryReadFileSystem`/`MemoryFileSystem` with
  `options.spzVersion: 4`. CPU-only, but RAM ~20× file size (raccoon peaked at
  1.24 GB) — a 50 MB upload would be memory-hungry in the API container
  (flagged, no guard yet).
- The splat's bounding box is `GSplatComponent.instance.meshInstance.aabb`
  (`boundingBox` does not exist on the component; `addComponent()` returns the
  component, typed nullable — use optional chaining).
- The SPZ viewer shows the **indeterminate sweep** while loading (PlayCanvas
  gives no byte progress for a single spz fetch); GLB keeps the determinate
  byte bar via `useLoader`'s progress callback.
- GLB load failures throw into the R3F canvas tree, which a DOM-level error
  boundary never sees — the in-canvas `components/ErrorBoundary.tsx` catches
  them and reuses the SPZ error UI. (R3F's own `ErrorBoundary` exists but is
  not re-exported from the package root.)
- **Review round (commit `dca0912`)**: a code-review pass found and we fixed —
  the seeded-prune scope (above), duplicated check→convert→store code
  (`ensureSpzV4`), the missing GLB error state, the documented client cap in
  `ModelControls` (mirrors the backend default, ImageDropzone pattern), and the
  stale build-log bullets.
- One new DB migration: `20261018000000_model_seeded` (the `Model.seeded`
  flag), applied via `npx prisma migrate deploy` + `npx prisma generate` in the
  api container. `ModelFormat` is still GLB | SPZ; the v2/v3 → v4 file
  *contents* changed in place (`npx @playcanvas/splat-transform <in> <out>`,
  v4 is the default anyway).

## Dev-environment gotchas (new this session)

- Adding a dependency requires refreshing the **lock files on the host first**
  (`npm install` in `frontend/` and `backend/`) — the image's `npm ci` fails on
  a stale lock.
- Backend `tsc` inside the container prints help (no tsconfig in the image) —
  typecheck on the host.
